# ชุดโค้ดระบบข้อสอบ Competency (SE) — คู่มือสำหรับผู้แก้ผ่าน Kiro

แพ็กจากโปรเจค Retail-COMM commit `{{COMMIT}}` วันที่ {{DATE}} · โฟลเดอร์นี้มีเฉพาะโค้ดของระบบข้อสอบกับไฟล์อ้างอิงที่จำเป็น **ไม่ใช่โปรเจคทั้งหมด**

## ขอบเขตการแก้

- **แก้ได้** = ไฟล์ที่อยู่ใน `MANIFEST.json` หมวด `editable` (ทุกไฟล์ใต้ `src/app/app/exam`, `src/app/api/exam`, `src/app/api/cron/exam-reminders`, `src/components/commission/exam`, และ `src/lib/server/exam.ts`, `src/lib/commission/exam-store.ts`, สคริปต์ `scripts/*exam*`, `scripts/sql/exam-phase1.sql`) เพิ่มไฟล์ใหม่ได้เฉพาะใต้โฟลเดอร์เหล่านี้
- **อ่านอย่างเดียว** = หมวด `readonly` (ไฟล์ที่ระบบข้อสอบ import มาใช้ เช่น Icon, boq-shared, auth-context, service client, push, ธีม Tailwind) **ห้ามแก้** เพราะมีผลกับส่วนอื่นของแอปที่ไม่ได้อยู่ในชุดนี้ ถ้าต้องแก้จริงให้เขียนเป็นข้อเสนอใน `CHANGES.txt` แทน
- ไม่มีและไม่ต้องขอ: `.env`, รหัสผ่าน, ข้อมูลพนักงาน/ร้านค้า, ไฟล์ข้อสอบต้นฉบับ (เฉลย), ฐานข้อมูลจริง

## ระบบข้อสอบทำงานอย่างไร (สรุป)

- ผู้สอบ = พนักงานขาย SE (บัญชีที่ผูกรหัสพนักงาน) · Admin เปิด **รอบสอบ** (ชื่อ, วันเริ่ม, เดดไลน์, เกณฑ์ผ่าน 80%) · SE ต้อง **ผ่านทุกหัวข้อ** (1 ชีตใน Excel = 1 หัวข้อ)
- สอบทีละหัวข้อ: ระบบสุ่มลำดับข้อและลำดับตัวเลือกต่อการสอบ 1 ครั้ง · **ต้องตอบครบทุกข้อจึงส่งได้** (ตรวจทั้งหน้าจอและ server) · บันทึกคำตอบอัตโนมัติ ปิดแล้วกลับมาทำต่อได้ · ตกแล้ว **สอบใหม่ได้ไม่จำกัดครั้ง** · ผ่านหัวข้อแล้วสอบซ้ำไม่ได้ · **ไม่แสดงเฉลย** (ผลสอบมีแค่คะแนน/ผ่านหรือไม่)
- สถานะหัวข้อ: `todo` (ยังไม่ทำ) / `in_progress` (กำลังทำ = ตอบไปแล้วอย่างน้อย 1 ข้อ) / `failed` (สอบใหม่) / `passed` (ผ่านแล้ว)
- ผู้ดู: Admin / หัวหน้า Area / Area / Coach / ร้านค้า ดูความคืบหน้าของ SE ตามขอบเขตร้าน (`/app/exam/progress`) · **Admin เท่านั้น** เห็นหน้า Top Rank (`/app/exam/ranking`: ใครสอบครบเร็วที่สุด, ใช้เวลาเป็น ชม./นาที/วินาที, รูปจากข้อมูลพนักงาน)
- Cron `/api/cron/exam-reminders` เตือนเดดไลน์ 7/3/1/0 วัน (Web Push)
- บัญชีทดสอบ (`is_test`) แยกข้อมูล: ผลสอบของบัญชีทดสอบไม่นับในรายงานจริง

## กติกาที่ต้องรักษา (ห้ามเปลี่ยนโดยไม่แจ้ง)

1. **ห้ามส่งเฉลยไปที่เบราว์เซอร์** — `is_correct` อ่านได้เฉพาะในฟังก์ชันตรวจคะแนนฝั่ง server การตอบ API ห้ามมีฟิลด์เฉลย/คำอธิบายเฉลย
2. สิทธิ์ตัดสินที่ **server** เสมอ (`getAuthContext()`) ปุ่มที่ซ่อนบนหน้าจอไม่ใช่การป้องกัน · รหัสพนักงานของผู้สอบมาจาก session ไม่ใช่จาก request
3. ตรวจ "ตอบครบทุกข้อ" ที่ server ต้องคงไว้ (หน้าจอปิดปุ่มอย่างเดียวไม่พอ)
4. การเปลี่ยนโครงสร้างฐานข้อมูล **ห้ามรันเอง** — ให้เขียนเป็น SQL ในไฟล์ใหม่ใต้ `scripts/sql/` + อธิบายใน `CHANGES.txt` ทีมหลักเป็นผู้นำไปรัน (ตารางเดิมมีข้อมูลจริง และอาจมีคนสอบไปแล้ว)
5. ห้ามเพิ่ม dependency ใหม่ (`package.json` ไม่อยู่ในชุดนี้) ถ้าจำเป็นต้องใช้ ให้เขียนเหตุผลใน `CHANGES.txt`
6. ห้ามใส่ข้อมูลจริง (ชื่อพนักงาน ร้าน ลูกค้า) หรือความลับ (key, token) ในโค้ด ตัวอย่าง และ `CHANGES.txt` — ชุดที่ส่งกลับจะถูกสแกนและปฏิเสธถ้าพบ

## ข้อควรระวังทางเทคนิค (เจอมาแล้วในโปรเจคนี้)

- Next.js 16 App Router + React 19 + `cacheComponents` เปิดอยู่: **ห้ามใช้ `export const dynamic`** ในหน้า/Route Handler ; หน้าใหม่ครอบ `<Suspense>` และใส่ `export const instant = false`
- **ไฟล์ `route.ts` export ได้เฉพาะ handler** (GET/POST/PUT/PATCH...) ฟังก์ชันช่วยให้ย้ายไป `src/lib/server/exam.ts`
- หน้าที่ถือ "ผลของการสอบครั้งหนึ่ง" ต้องมีตัวแยกครั้งใน URL (เดิมใช้ `?v=<เวลา>` ตอนกดเริ่ม/สอบใหม่) ไม่งั้น Next เก็บสถานะหน้าเดิมไว้ ผลสอบครั้งก่อนจะค้าง
- ESLint `react-hooks/set-state-in-effect`: อย่าเรียก setState ตรง ๆ ในตัว useEffect (ตั้งใน callback ของ fetch/event handler)
- API ที่อ่านตารางใหญ่ต้องแบ่งหน้า (PostgREST คืนสูงสุด 1,000 แถวต่อครั้ง) — ที่ต้องการสรุปทั้งรอบใช้ฟังก์ชันฐานข้อมูล (`exam_progress`, `exam_ranking`) ที่คืน jsonb ก้อนเดียว
- ชื่อไทยในวงกลมตัวย่อ: ข้ามสระหน้า (เ แ โ ใ ไ) แล้วตัดทีละ grapheme (`Intl.Segmenter`)
- ใช้ `str_replace` แก้ไฟล์ทีละจุด ไม่ใช้สคริปต์แทนที่ข้อความทั้งไฟล์ (เคยทำไฟล์เสียเพราะตัวขึ้นบรรทัดใหม่)

## สิ่งที่ทำไม่ได้ในชุดนี้

ชุดนี้ไม่มี `package.json`, `node_modules`, `.env` จึง **รันแอปหรือ `tsc` ไม่ได้** ให้ตรวจโดยอ่านโค้ด ตามรูปแบบของไฟล์เดิม และตามชนิดข้อมูลใน `exam-store.ts` ให้ละเอียด ทีมหลักจะรัน typecheck + lint + ทดสอบกับระบบจริงก่อนรวม

## ส่งกลับอย่างไร

1. ส่งโฟลเดอร์นี้ทั้งก้อน (zip) กลับมา **โดยไม่เปลี่ยนชื่อ/ที่อยู่ไฟล์** และ **ห้ามลบ `MANIFEST.json`** (ใช้ตรวจว่าแก้ไฟล์ไหนบ้าง)
2. เพิ่มไฟล์ `CHANGES.txt` ที่รากโฟลเดอร์: แก้อะไรบ้าง (ไฟล์ไหน เพราะอะไร) · มีการเปลี่ยนฐานข้อมูลหรือไม่ (ถ้ามีแนบไฟล์ SQL) · สิ่งที่ยังไม่ได้ทดสอบ · ข้อเสนอแก้ไฟล์ readonly (ถ้ามี)
3. ไฟล์ที่แก้นอกขอบเขต (readonly/นอกโฟลเดอร์ข้อสอบ) จะถูกปฏิเสธ ไฟล์ที่ทีมหลักแก้ไปแล้วหลังแพ็กจะไม่ถูกเขียนทับ ต้องผสานด้วยมือ
